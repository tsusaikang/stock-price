# 오늘 뭐가 튀었나

한국 주식이 얼마나 오르고 얼마나 떨어졌는지 **클릭 없이 첫 화면에서** 보는 도구.

기존 포털의 문제(원하는 화면까지 3~4번 터치, 종목 갈아타기 번거로움, 관심종목이
어디에도 저장 안 됨)를 없애는 걸 목표로 만들었다. 실시간 시세가 목적이 아니라
"뭐가 튀었나"를 빨리 훑는 게 목적이라 1~2분 묵은 값은 허용한다. 대신 화면 상단에
**그 값이 몇 시 기준인지** 항상 찍는다.

**주소: https://stock.dwnc.me**

## 화면

- **지수 + 급등/급락 TOP 15** — 첫 화면에 바로. 종목마다 30일 스파크라인이 붙어서
  오늘 급등이 반등인지 추세인지 한눈에 구분된다.
- **탭 하나로 종목 펼침** — 페이지 이동 없이 그 자리에서 일봉 차트(1개월/3개월/1년),
  시·고·저·거래량이 펼쳐진다. 차트를 손가락으로 문지르면 그날 종가와 등락률이 나온다.
- **★ 관심종목** — 브라우저(localStorage)에 저장. 로그인 없음. 첫 화면 맨 위 고정.
- **이슈 탭** — 네이버 검색량 상위 종목. 모르던 종목을 발견하는 용도.
- **관련 종목 추천** — 아래 참고.
- **홈 화면에 추가** — 매니페스트·아이콘이 있어 안드로이드에서 앱처럼 설치된다.

상승 빨강 / 하락 파랑(국내 관행). 다크모드 자동.

## 관련 종목 추천이 동작하는 방식

종목을 펼치면 세 가지가 같이 나온다.

| 구분 | 근거 |
|---|---|
| 같은 업종 | 네이버 업종 분류 (`industryCompareInfo`) |
| 같이 움직이는 종목 | 최근 60거래일 **일간수익률 상관계수** 상위 |
| 반대로 움직이는 종목 | 같은 상관계수의 하위 (−0.1 미만만) |

상관계수 쪽이 업종을 넘나드는 발견을 만든다. 두산에너빌리티를 보면 같은 업종 칸에는
두산밥캣·로보틱스가 뜨지만, 상관계수 칸에는 비에이치아이·현대건설·한전기술·대우건설처럼
분류상 남남인데 원전·건설로 실제 같이 움직인 종목이 올라온다. "반대로 움직이는 종목"은
지수가 무너진 날 뭘 들고 있어야 버텼는지 보는 칸이다.

후보군은 코스피·코스닥 시총 상위 각 200종목에 그날 급등·급락·검색상위를 더한 약 440종목.
ETF·ETN과 우선주는 뺀다. 인버스 레버리지 상품은 지수가 크게 움직인 날 급등·급락 랭킹을
통째로 차지해버려서 "무슨 **종목**이 튀었나"를 가려버린다.

후보마다 **자기 마지막 날짜에 맞춰** 기준 종목을 잘라서 비교한다. 위치로만 맞추면 장중엔
기준 종목에만 오늘 봉이 붙어 있어 하루씩 어긋난 값끼리 비교하게 된다.

## 구조 — Cloudflare Workers 무료 플랜

```
src/worker.js     진입점: /api/* 라우트와 cron
src/naver.js      네이버 금융 호출 (캐시 없음, 호출마다 예산 차감) · ETF/우선주 판별
src/store.js      D1: 화면 스냅숏(blob), 종목별 최근 종가(series), 잠금, 스키마
src/home.js       첫 화면 = 가격 단계 + 스파크라인 보충 단계
src/universe.js   관련종목 후보군 재구축 (단계별)
src/related.js    상관계수 (순수 계산)
src/util.js       한국 시간 계산, 외부 요청 예산
public/           index.html · app.js · style.css (프레임워크 없음, SVG 차트 직접 그림)
```

무료 플랜의 제약이 구조를 정했다 (2026-11-10 공식 문서로 확인):

| 제약 | 값 | 그래서 |
|---|---|---|
| 호출당 외부 요청 | **50개** | 모든 네이버 호출이 예산을 차감 |
| 호출당 CPU | **10ms** (네트워크 대기는 제외) | 아래 실측 참고 — 호출당 외부 요청을 ~10개 이하로 |
| 메모리 캐시 | 인스턴스가 언제든 바뀜 | 스냅숏·종가는 D1에 둔다 |
| cron 실행 위치 | 보장 없음 | 사용자가 기다리는 경로엔 안 쓰고, 미리 데우는 데만 쓴다 |
| cron 개수 | 계정 전체 5개 | 1개만 쓰고 시각을 보고 할 일을 고른다 |
| 정적 파일 | 무료·무제한, Worker 안 거침 | `public/`은 그대로 |
| 응답 뒤 작업 | 30초 뒤 취소 | 시한(20초)을 두고, 가격은 먼저 저장 |

### CPU 실측 (Cloudflare 실서버, 2026-11-10)

처음 배포한 버전은 상세 화면 18ms, 후보군 단계 31~87ms로 한도를 꾸준히 넘었다(오류는 없었음).
측정 전용 경로로 구간을 나눠 재 보니 원인은 세 가지였다.

| 구간 | CPU | 원인과 조치 |
|---|---|---|
| 외부 요청 1개 | **~1ms** | 내려받은 용량보다 **개수**가 비용. 4KB 일봉 45개 = 31~87ms, 190KB 랭킹 4개 = 17ms. → 호출당 ~10개 이하로 쪼갬 |
| D1 BLOB 읽기 | 4~8ms | D1이 BLOB을 숫자 10만 개짜리 **JS 배열**로 돌려준다. → base64 문자열로 저장 |
| 스키마 확인 | 1~6ms | 요청이 드물어 거의 매번 새 인스턴스. → "no such table" 오류가 날 때만 생성 |

조치 후: 첫 화면 1~4ms, 관심종목 4~6ms, 검색 1~2ms, cron 5~14ms, 상세 화면 6~25ms(중앙값 ~13).
상세 화면이 들쭉날쭉한 건 새 인스턴스에서 처음 실행될 때의 컴파일 비용이다. 하루 몇 번 15ms
남짓이라 그대로 둔다. 다시 재려면 대시보드 Observability → Events의 `$workers.cpuTimeMs`.

**첫 화면 (`/api/home`)** — D1에 저장된 스냅숏을 바로 준다.
- cron이 장중(평일 08:30~15:45) 가격을 두 묶음으로 나눠 1분씩 번갈아 받는다:
  A = 지수+급등+급락(요청 5), B = 이슈+시총(요청 4). 묶음마다 약 2분 간격.
  B 차례엔 남는 몫으로 스파크라인을 보충한다. 장 마감 뒤엔 15:45 이후 값으로 한 번씩 더.
- 스냅숏이 없거나 장 상태가 어긋났으면(아침에 어제 마감 화면 등) 기다려서 새로 받는다.
- 그냥 묵은 정도면 저장분을 주고 뒤에서 묶음 A만 갱신하면서 `stale: true`를 붙인다.
  화면은 그걸 보고 2.5초 뒤 한 번 더 받는다.
- 갱신은 D1 잠금을 잡고 한 곳에서만 한다(cron·사용자 요청이 겹치지 않게).

**관련종목 후보군** — 하루 한 번 장 마감 뒤 cron이 1분에 한 단계씩 다시 받는다:
코스피 시총 → 코스닥 시총 → 급등락 → 검색상위 → 일봉 10종목씩 약 44번 → 실패분 재시도 →
**포장**(최근 60일 수익률을 Float32 행렬 하나로, base64 104KB). 상세 화면은 포장본 한 행만 읽고,
같은 인스턴스에선 10분간 메모리에 둔다. `/api/universe`를 열면 진행 상황을 보여주고, 덜 됐으면
한 단계 진행한다.

**네이버 일괄 조회** — `polling.finance.naver.com/api/realtime/domestic/stock/코드,…`가
200종목까지, `…/domestic/index/KOSPI,KOSDAQ`가 지수 둘을 한 요청으로 준다. 상세 화면은 이 종목
시세와 관련종목 칩 12개를 요청 하나로 받는다. 단 종목 일괄 조회의 `localTradedAt`은 체결 시각이
아니라 **요청 시각**이라 거래일 판단에 쓰면 안 된다(지수 쪽은 실제 시세 시각이다).

### 검토했지만 안 쓴 것

- **Durable Object 하나로 캐시+스케줄러** — 지금 Node 서버와 가장 닮은 구조고 저장소가 연산
  옆이라 빠르다. 다만 처음 호출된 위치에 영구히 고정된다(D1도 생성 위치에 고정되는 건 같다).
  D1+cron을 고른 이유는 그쪽이 문서화된 무료 한도가 더 명확하고, cron이 설정 파일에 드러나고,
  데이터를 대시보드에서 바로 볼 수 있어서다.
- **Workers Paid($5/월)** — 호출당 외부 요청 1만 개, CPU 30초라 거의 그대로 옮길 수 있다.
  비용 때문에 무료로 갔다.
- **KV** — 무료 쓰기가 계정 전체 하루 1,000회라 1분마다 쓰기엔 다른 프로젝트와 겹친다.

## 배포

GitHub(`tsusaikang/stock-price`) `main`에 푸시하면 Cloudflare **Workers Builds**가 받아서
`npx wrangler deploy`를 돌린다. 계정은 **tsusaikang@gmail.com**, Worker 이름 `stock-price`,
빌드 토큰 `stock-price build token`(이 Worker 전용), D1 `stock-price`(APAC).

- 이 맥의 wrangler는 **다른 계정(amxrank)에 로그인돼 있다.** 여기서 `wrangler deploy`나
  `wrangler login`을 하지 말 것 — 엉뚱한 계정에 올라가거나 amx 프로젝트 배포가 꼬인다.
- 도메인은 `wrangler.jsonc`의 `routes`가 배포 때마다 맞춘다. 대시보드에서 따로 붙이지 않는다.
- D1 스키마는 코드가 스스로 만든다(`src/store.js`). 마이그레이션 명령을 돌릴 곳이 없어서다
  (빌드 토큰엔 D1 권한이 없고, 로컬 wrangler는 다른 계정). 컬럼을 추가할 땐 `MIGRATIONS`
  배열 끝에 `ALTER TABLE` 묶음을 붙인다.
- **푸시했는데 빌드가 안 걸리면** 대시보드 Worker → Deployments → 아무 빌드 → **Retry build**.
  (`commit`이 비어 있는 수동 빌드라 그때의 `main` 최신을 받아 간다.)

### 배포하면 확인할 것

```bash
curl -s https://stock.dwnc.me/api/diag
```

네이버 7개 엔드포인트가 이 Worker에서 닿는지, 어느 데이터센터(`colo`)에서 돌고 있는지,
D1 왕복이 몇 ms인지 한 번에 본다. 모든 요청에는 `CF-Worker: dwnc.me` 헤더가 붙어서
네이버가 마음먹으면 막을 수 있다 — 막히면 여기서 바로 보인다.

```bash
curl -s https://stock.dwnc.me/api/universe
```

관련종목 후보군 진행 상황. 첫 배포 직후엔 비어 있으니 `done: true`가 될 때까지 몇 번 연다.

## 로컬 개발

```bash
npm install
npm run dev        # http://127.0.0.1:8787 — 실제 Workers 런타임, D1은 로컬 SQLite
```

계정에 접속하지 않는다. cron은 `curl "http://127.0.0.1:8787/__scheduled?cron=*+23,0-8+*+*+*"`로
흉내 낸다. 로컬 D1을 들여다보려면 `npx wrangler d1 execute stock-price --local --command "…"`.

`npm run check`는 배포 없이 번들만 만들어 본다.

## 데이터 출처와 한계

시세는 전부 **네이버 금융의 비공식 JSON 엔드포인트**에서 온다. 공개 문서가 없는
API라서 **네이버가 응답 형식을 바꾸면 깨질 수 있다.** 개인용 도구라 감수한 선택이고,
파싱은 전부 방어적으로 짜서 한 칸이 실패하면 그 칸만 이전 값으로 남는다.

대안을 검토했지만 이 용도에는 맞지 않았다.

- **KRX 정보데이터시스템** — 세션 쿠키를 먼저 받아야 하고 (`LOGOUT` 응답) 번거롭다.
- **공공데이터포털 주식시세정보** — 정식 API지만 급등·급락 랭킹이 없고 T+1 종가만 준다.
- **한국투자증권 KIS Developers** — 정식이고 실시간이지만 계좌 개설이 필요하다.

그 외 알아둘 것:

- 랭킹 API는 `pageSize`가 **100이 상한**이다. 넘기면 JSON 대신 HTML을 돌려준다.
- 시장(`KOSPI`/`KOSDAQ`)을 따로 불러 합쳐야 한다. `ALL`은 지원되지 않는다.
- ETF 판별은 종목명 기반 추정이다. 운용사 브랜드 뒤에 공백이 오는 패턴(`삼성 인버스 2X …`)을
  쓰는데, 국내 종목명은 공백을 거의 안 써서 `삼성전자`·`KB금융`·`HK이노엔` 같은 실제 회사는
  걸리지 않는다. (예외적으로 공백 쓰는 종목: `LS ELECTRIC`, `JYP Ent.`, `CJ ENM`, `NHN KCP`)
- 일봉(siseJson)의 전일 종가와 시세 API의 등락폭 기준가가 가끔 다르다(통합시세 기준 차이로
  보인다). 스파크라인은 일봉 원본을 그대로 그린다.
