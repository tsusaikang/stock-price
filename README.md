# 오늘 뭐가 튀었나

한국 주식이 얼마나 오르고 얼마나 떨어졌는지 **클릭 없이 첫 화면에서** 보는 도구.

기존 포털의 문제(원하는 화면까지 3~4번 터치, 종목 갈아타기 번거로움, 관심종목이
어디에도 저장 안 됨)를 없애는 걸 목표로 만들었다. 실시간 시세가 목적이 아니라
"뭐가 튀었나"를 빨리 훑는 게 목적이라 캐시를 넉넉히 쓴다.

## 실행

```bash
node server.js
```

의존성이 하나도 없다. `npm install` 필요 없음. Node 20 이상이면 된다.

띄우면 터미널에 로컬 주소와 **같은 와이파이에서 폰으로 접속할 주소**가 같이 찍힌다.

## 배포 (Railway)

GitHub에 푸시하면 Railway가 받아서 `node server.js`를 대신 실행한다. 설정은
`railway.json`에 들어 있고 따로 손댈 게 없다.

1. github.com에 빈 저장소를 만든다 (README·.gitignore 체크 해제).
2. `git remote add origin git@github.com:<계정>/<저장소>.git && git push -u origin main`
3. railway.app → New Project → Deploy from GitHub repo → 저장소 선택.
4. Settings → Networking → **Generate Domain**. `https://….up.railway.app` 주소가 나온다.

### 배포하면 반드시 확인할 것

Railway는 해외 리전(싱가포르)에서 돌기 때문에 **네이버가 해외 IP를 막는지**가 최대
변수다. 배포 직후 이걸 친다.

```bash
curl -s https://<주소>/api/diag?fresh=1
```

6개 엔드포인트를 실제로 때려보고 어디가 막혔는지 알려준다. `egress`에 서버가 어느
나라에서 나가는지도 찍힌다. 서울에서 돌린 기준선은 전부 통과에 30~170ms다.

`일봉차트`(`api.finance.naver.com`)가 실패하면 차트와 관련 종목 추천이 통째로 죽는다.
그 경우 대안은 (1) 도쿄 리전이 있는 Fly.io로 옮기거나, (2) 일봉만 다른 소스로 바꾸는 것.

### 공개 URL로 열 때

인증이 없어서 주소를 아는 사람은 누구나 쓴다. 다만 캐시가 상한을 잡아준다 — 시세 60초,
일봉 5분이라 트래픽이 몰려도 네이버로 나가는 호출은 그만큼 늘지 않는다. 새 종목 하나당
upstream 호출은 4번 정도다.

## 화면

- **지수 + 급등/급락 TOP 15** — 첫 화면에 바로. 종목마다 30일 스파크라인이 붙어서
  오늘 급등이 반등인지 추세인지 한눈에 구분된다.
- **탭 하나로 종목 펼침** — 페이지 이동 없이 그 자리에서 일봉 차트(1개월/3개월/1년),
  시·고·저·거래량이 펼쳐진다. 차트를 손가락으로 문지르면 그날 종가와 등락률이 나온다.
- **★ 관심종목** — 브라우저(localStorage)에 저장. 로그인 없음. 첫 화면 맨 위 고정.
- **이슈 탭** — 네이버 검색량 상위 종목. 모르던 종목을 발견하는 용도.
- **관련 종목 추천** — 아래 참고.

상승 빨강 / 하락 파랑(국내 관행). 다크모드 자동.

## 관련 종목 추천이 동작하는 방식

종목을 펼치면 세 가지가 같이 나온다.

| 구분 | 근거 |
|---|---|
| 같은 업종 | 네이버 업종 분류 (`industryCompareInfo`) |
| 같이 움직이는 종목 | 최근 60거래일 **일간수익률 상관계수** 상위 |
| 반대로 움직이는 종목 | 같은 상관계수의 하위 (−0.1 미만만) |

상관계수 쪽이 업종을 넘나드는 발견을 만든다. 예를 들어 삼성전자를 보면 같은 업종
칸에는 SK하이닉스·한미반도체가 뜨지만, 상관계수 칸에는 건자재인 KCC(+0.71)처럼
분류상 남남인데 실제로는 같이 움직인 종목이 올라온다. "반대로 움직이는 종목"은
지수가 무너진 날 뭘 들고 있어야 버텼는지 보는 칸이다.

후보군은 코스피·코스닥 시총 상위 각 200종목에 오늘 급등·급락·검색상위를 더한
약 400종목이고, 서버가 뜰 때 미리 일봉을 받아둬서(1초 남짓) 조회는 즉시 끝난다.

ETF·ETN과 우선주는 후보에서 뺀다. 인버스 레버리지 상품은 지수가 크게 움직인 날
급등·급락 랭킹을 통째로 차지해버려서 "무슨 **종목**이 튀었나"를 가려버린다.

## 구조

```
server.js          정적 서버 + 네이버 프록시 (브라우저에서 직접 부르면 CORS에 막힌다)
lib/naver.js       네이버 금융 API 클라이언트 · 캐시 · ETF/우선주 판별
lib/related.js     상관계수 기반 관련 종목
public/            index.html · style.css · app.js (프레임워크 없음, SVG 차트 직접 그림)
```

캐시 TTL은 시세·랭킹 60초, 일봉 5분. `lib/naver.js`의 `TTL`에서 조정한다.

## 데이터 출처와 한계

시세는 전부 **네이버 금융의 비공식 JSON 엔드포인트**에서 온다. 공개 문서가 없는
API라서 **네이버가 응답 형식을 바꾸면 깨질 수 있다.** 개인용 도구라 감수한 선택이고,
파싱은 전부 방어적으로 짜서 한 종목이 실패해도 화면 전체가 죽지는 않는다.

대안을 검토했지만 이 용도에는 맞지 않았다.

- **KRX 정보데이터시스템** — 세션 쿠키를 먼저 받아야 하고 (`LOGOUT` 응답) 번거롭다.
- **공공데이터포털 주식시세정보** — 정식 API지만 급등·급락 랭킹이 없고 T+1 종가만 준다.
  이 앱의 핵심 요구를 못 채운다.
- **한국투자증권 KIS Developers** — 정식이고 실시간이지만 계좌 개설이 필요하고,
  실시간성이 목표가 아닌 이 앱에는 과하다.

그 외 알아둘 것:

- 랭킹 API는 `pageSize`가 **100이 상한**이다. 넘기면 JSON 대신 HTML을 돌려준다.
  (`fetchRanking`이 100씩 나눠서 받는다.)
- 시장(`KOSPI`/`KOSDAQ`)을 따로 불러 합쳐야 한다. `ALL`은 지원되지 않는다.
- ETF 판별은 종목명 기반 추정이다. 종목코드로는 구분이 안 된다. 운용사 브랜드 뒤에
  공백이 오는 패턴(`삼성 인버스 2X …`)을 쓰는데, 국내 종목명은 공백을 거의 안 써서
  `삼성전자`·`KB금융`·`HK이노엔` 같은 실제 회사는 걸리지 않는다.
  (예외적으로 공백 쓰는 종목: `LS ELECTRIC`, `JYP Ent.`, `CJ ENM`, `NHN KCP`)

인과관계나 미래 예측이 아니다.
